# Pinned Usage reference setting verification

The original delegate is retained byte-exact with its copyright/license header.
It is portable verification data only. Normal native provider activation/reload
uses the registered handwritten Rust implementation, the exact native schema
and checked contracts; it needs no JVM or upstream Java checkout.

`usage_reference_delegate_source` reports compiled-in provenance. The optional
verification function rejects altered source text but does not install a provider.
Raw legacy DerivedValues support does not activate a prepared semantic-read
session. That future policy must use its own fallible dependency reader and may
share the pure Boolean involution. Only Set(bool) is implemented; Unset and
constructor/prefix defaults remain separate proofs.

The portable20-row fresh-Pilot corpus verifies Usage and PartUsage typed/
reflective getter and Set values. Java raw fields, eGet and eIsSet remain
distinct observations. Upstream eIsSet(isReference) remains true even when
the getter is false; that operation is not implemented or inferred here.

The focused text fixture supplies elementId in its source input and direction
explicitly. It does not implement the original language constructor, UUID
generation or prefix defaults. Full ordinary SysML still fails FragmentCallers
work admission under unchanged limits.
