# Independent parameter entry contexts

This fixture extends the original imported-parameter observations without changing
their sources or expectations. It is independent evidence before native entry
adoption; full parameterization, X03/X07/X10 and S09 remain OPEN.

Ten exact imported-only graphs retain nine metadata acceptances and one rejection.
Seven graphs generate compiled parsers. Two metadata-accepted first-scalar graphs
retain explicit upstream generator obstructions (no production rules and an
EDataType/EClass cast); their twelve requests were not executed. The rejected
assigned-fragment graph retains six further unexecuted requests. The seven compiled
graphs execute 38 registered parser/resource requests: 16 rooted models, 19 errors
or entry exceptions, and three error-free rootless parses. Seven unregistered
provider-context probes remain separate observations.

Twenty-five additional probes invoke the actual generated entry methods, with the
pinned parser's token stream, providers and node builder initialized as in its
ordinary parser wrapper. They record full public-entry inventories, declared return
types, scalar/model/partial return values and node-model errors. A scalar named
entry can return a string although IParser reports no EObject root. Failed parses
may retain partial scalar returns; this does not qualify native partial-result
semantics. ANTLR's numeric error counter can remain zero for a real node-model
syntax error, so it is retained as supplementary information, never acceptance.

False-only/both/dead-guard datatype contexts, unreachable plain declarations,
false wildcard/typed fragments and unassigned datatype-fragment forwarding remain
distinct graphs. The assigned fragment rejection is preserved separately. Exact
frozen imported Ecore bytes come from original independent providers; ordinary
grammars generate no Ecore. Java is exclusively an independent verification oracle.

The original preimplementation plans and every failed/context-mismatched capture,
including the initial counter-only return probe, remain in the primary checkout's
ignored target/rcore-xtext-support-evidence. No native support is awarded here.

Offline integrity and completeness verification needs no Java or network:

~~~sh
python -B fixtures/xtext/parameter-entry-contexts/verify.py
~~~

Fresh read-only replay requires explicit JDK and populated pinned Maven cache:

~~~sh
python -B fixtures/xtext/parameter-entry-contexts/verify.py --replay target/parameter-entry-readonly --java-home /path/to/jdk --maven-cache /path/to/maven/repository
~~~

Replay creates a new output directory outside fixtures, reproduces the expected
generator obstructions, and compares complete canonical observations. It has no
expectation-update option. Existing immutable metadata/runtime adapters are shared
by exact component hash; assemble.py normalizes generator diagnostic ordering while
complete raw generation logs remain in the replay output.
