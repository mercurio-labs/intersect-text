# Rule-local hidden-token evidence

This corpus preserves 51 exact source graphs through source loading, linking,
validation, generation, Java compilation, lexer, named parser and resource stages.
Original invalid recipes, separately identified namespace companions and later
boundary/reference/delegation controls retain their own source IDs and outcomes.
They are never substituted for one another.

Per original record/replay run, 22 graphs reach clean generation and compilation;
29 stop at source or generation failures. Of 463 planned resource probes, 243
execute: 98 accept and 145 reject, including 122 rejected partials. The other 220
remain unexecuted. These partials are independent upstream observations, not valid
native model publications.

There are 280 planned additional named calls and 178 complete named JSON
observations. Those 178 comprise 155 executed IParser observations (56 accepted,
99 syntax-rejected) and 23 generated-entry availability/workflow failures
(NoSuchMethodException). Availability failures are not parsed-model rejections.
The named helper also repeats the default resource observation; that repetition
does not add distinct resource probes. Native resource execution includes linking;
named IParser acceptance alone does not establish resolved references.

Run `python verify.py --storage-negatives` for pure byte, storage, source-identity,
stage and original record/replay integrity. It requires no Java or native build.
Native JSONL storage is deterministic gzip: the verifier checks compressed bytes,
bounded decompression, original raw length/SHA-256 and every complete original row.
Upstream source/generated/workflow/output artifacts remain raw and unchanged.
The original raw native captures remain independently preserved outside this
portable directory.

Optional regeneration uses `python oracle-producer/replay.py --help`; it requires
the pinned local JDK and sixty verification-only jars and a new output root.
Original producers and helpers remain byte-exact under oracle-producer/original;
the wrapper adapts path discovery only. Fresh outputs never replace this baseline.
The only comparison exception is the exact owned absolute
provider-<EcoreSHA12>/provider.genmodel output location. Source, TypeRef, grammar
resource and diagnostic identities are never normalized.

Historical helpers and failures remain separate: the first output guard stopped
before creating hsv1r (explicit absent marker); the original text-mode transport
lost unavailable Unicode output bytes rather than establishing rejection. Later
binary/strict-UTF-8 helpers, calibration and logical-to-physical loader bindings
are separate addenda, not reconstructed original observations.

NativeV64 consumes the exact original source graphs with a separately identified
canonical Rcore structural adapter. This is not native Ecore import qualification.
Its retained lexical winners and contextual hidden policy are temporary parsing
state. Durable source/model nodes, significant-trivia services, incomplete-editor
recovery and the remaining full X04–X07/X15/S09 obligations remain open.
