# Cumulative KerML rule-converter example

Select **KerML rule converters**. The authored grammar extends the enum showcase
under a separate namespace and source identity. It preserves inherited grammar
rules, typed fragments, actions, inferred string datatypes, enums, numeric
spellings, quoted qualified names, documentation and cross-resource references.

Two resources construct seven objects. The front feature uses ordered nonunique,
while spare reverses those modifiers. Both become isUnique=false and
isOrdered=true. The standard feature omits the modifiers and keeps isUnique=true.
Ordinary enabled true/false values use the shared Boolean codec; they are not
subject to the Nonunique converter. Visibility and direction retain exact enum
literal identities, and all three feature targets resolve locally or across files.

The exact pinned Nonunique and BooleanValue grammar fragments are consumed.
model-behavior.rcore explicitly binds the former to a language-owned keyword-to-Boolean
provider, identifying the root grammar, parent declaration source digest/span,
return datatype and provider version. No rule-name heuristic or global Boolean
codec replacement is used. This fixture is not the actual pinned KerML metamodel;
its domain multiplicity, membership visibility and derived operands are unqualified.

Change enabled true to enabled maybe, or repeat nonunique, to see resource rejection.
Restoring the text restores the model. Project reopen and downloaded language ZIP
replay preserve all source definitions, converter policy and resulting values.
Use the inspector to compare front and standard. Returning to Library retains its
existing circulation, validation and generated API behavior.

Run python -B fixtures/xtext/converter-showcase/verify.py for byte provenance.
The seven original enum-showcase files remain untouched; all nine pinned terminal
slices and both pinned datatype-rule slices retain their exact bytes. The upstream
notice and EPL-2.0 license remain present. Independent converter provenance and
cached observations live in ../rule-converters/provenance.json.
