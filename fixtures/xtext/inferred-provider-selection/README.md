# Native inferred provider selection and contextual preview

Frozen against 89b5ef67 before implementation. This is native-extension consumer
evidence, not independent JVM qualification or durable project recovery.

The four successful source graphs are copied exactly from the existing scalar
and collection computed-host plans. Existing checked contexts are retained as
independent expected outputs. No original fixture or failure is replaced.

Selectors identify an exact original authored Rcore SourceId, namespace, class
and feature spelling, plus explicit installed provider and operation choices.
Native source resolution creates all runtime class/member identities and schema
revisions. Generated, inherited and generic members are outside this first
selector-origin profile and must reject explicitly rather than use name fallbacks.
Missing/stale/duplicate/ambiguous/unsupported/unused selectors reject. A successful
selected compile is distinct from the structural candidate catalog.

Selection is bounded to sixteen members. After full contextual compilation, the
same compiler is run with each contract omitted to prove actual admission use.
This synchronous bounded helper is not a cooperative S09 closure. Extra declared
script operations may be useful even though grammar writes use only Set/Append.

The explicit contextual preview recompiles original inference inputs with checked
context before resolving an exact freshly generated source. Legacy preview still
rejects context options. Generated programs, package/schema JSON and previous
preview DTOs never substitute for original source authority.

`before.json` records actual preserved-release requests and responses for the new
helper methods, legacy compilation, original model execution and previews. The
additional original graphs retain inherited, unused, generic and ambiguous
selection boundaries. Native/JSON/WASM controls must verify actual model values,
old failures, fresh selection after source edits and contextual preview structure.

A separate `unified.json` companion retains a genuine single Rcore source with
structure and behavior together. Its exact SourceId selects both the authored
receiver and behavior. That companion adds native execution/operation controls
without replacing the four original graphs above.
