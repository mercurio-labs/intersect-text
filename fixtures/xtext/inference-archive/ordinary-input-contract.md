# Historical ordinary archive input

`ordinary-baseline-input.rcore` is generated test data recovered by executing the
unmodified producer at `a7ea7155575214029d47905157ea55c43cb4c80a` in a `git archive`
snapshot with a separate Cargo target. Its manifest and both UTF-8 payload hashes
match every original observation in `ordinary-baseline.json`. Java was not used.
`ordinary-input-provenance.json` records the producer sources, command, exact input
identity and the independently retained original observation hash.

The original compatibility fixture migrated its Ecore input on every execution.
Two later changes (`203902dd`, annotation layout; `eeb500c4`, name spelling and
layout) changed the generated Rcore text. That also changed source identities,
schema revisions and archive digests before the Xtext separation began. A
comparison of today's newly generated text to the old archive observation was
therefore comparing different inputs.

The historical control now compiles the recovered Rcore text through the current
shared compiler, and compares its complete manifest, payload lengths/digests and
both actual Toolkit ZIP forms to the unchanged original expectations. It also
imports the result through both ordinary and language archive readers, and
rebuilds its exact retained recipe through the current producer. The ordinary
compatibility corpus continues to exercise today's migrator independently.

The recovered file's effective archive URI is `memory:model.rcore`, its UTF-8
length is 1,044 bytes and its SHA-256 is
`1829936c163c964bee941a362d72007914b0fae010525074f266efd3b2412194`.
Do not format or add comments to these generated bytes. Updating a renderer does
not authorize replacing the historical archive observations. These are
compatibility controls, not independent language-semantic qualification.

Legacy format-2 containers whose compiler identity is `intersect-model` also keep
their historical README text verbatim, including its old Rust loader path. That
text is part of the pinned byte contract. To load those archives with the current
crates, use `intersect_xtext::distribution::import_files` (or its `ordinary`
reader). The old model loader is not restored. Xtext-owned compiler identities
write the current loader path in their README. Source verification and executable
provider selection are enforced by the current reader for both identities.
